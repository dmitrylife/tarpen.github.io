# Tarpen

**Tarpen — общественный архив состояния инфраструктуры и территории.**

Проект предназначен для документальной фиксации локальных вопросов, связанных с инфраструктурой, доступностью, благоустройством и окружающей средой, а также для сохранения истории обращений, официальных ответов, повторных наблюдений и фактических изменений.

Сайт: https://www.tarpen.ru/

Первой территорией, представленной в архиве, является посёлок Тушино Неманского муниципального округа Калининградской области. Архитектура проекта позволяет добавлять другие территории.

## Основной принцип

> **Документы подтверждают движение обращения. Фактические изменения определяют состояние проблемы.**

Наличие обращения, регистрации или официального ответа само по себе не означает, что проблема устранена. Изменение состояния фиксируется повторным наблюдением и, когда это возможно, подтверждается фото-, видео- или иными материалами.

Tarpen не приписывает наблюдаемое изменение конкретному обращению или исполнителю без документального подтверждения такой связи.

## Что хранит Tarpen

Каждый вопрос оформляется как отдельный структурированный **кейс**. В нём могут содержаться территория и место, классификация, описание и установленные факты, исходные материалы, обращения, официальные ответы, повторные наблюдения, хронология и текущее фактическое состояние.

Кейсы находятся в коллекции `_cases/` и являются основным источником данных для публичного сайта.

## Паспорт территории · Territory Pulse

Tarpen автоматически формирует сводную картину по поддерживаемой территории.

Для Тушино опубликован **Паспорт территории**:

https://www.tarpen.ru/places/tushino/

Паспорт автоматически рассчитывает по опубликованным кейсам количество вопросов, распределение по состоянию, дату последней фиксации, повторные наблюдения, обращения и опубликованные ответы, тематическую структуру и документально зафиксированную динамику.

Для кейсов с повторной фотофиксацией используется сопоставление **«Исходная фиксация / Повторная фиксация»**.

Паспорт не является рейтингом территории или официальной статистикой. Он отражает только материалы, документально представленные в Tarpen.

## Модель данных

Основные сущности схемы кейса:

- `location` — территория и место;
- `classification` — тип и порядок отображения;
- `publication` — сведения о публикации и обновлении;
- `summary` — краткое описание;
- `case_status` — фактическое состояние;
- `findings` — установленные обстоятельства;
- `evidence` — исходные доказательные материалы;
- `interactions` — обращения и взаимодействия;
- `responses` — опубликованные официальные ответы;
- `observations` — повторные наблюдения;
- `timeline` — хронология.

Изменение данных кейса автоматически отражается на его странице, в агрегированных разделах и в паспорте территории после следующей сборки сайта.

## Архитектура

Tarpen — статический сайт на **Jekyll**, публикуемый через **GitHub Pages**.

```text
_cases/                 структурированные кейсы
_includes/              повторно используемые компоненты
_layouts/               шаблоны страниц
places/                 страницы и паспорта территорий
img/                    публикационные изображения
scripts/                служебные инструменты
.github/workflows/      автоматическая сборка и публикация
MANUAL.md               практическое руководство
```

GitHub Actions запускает Jekyll, формирует сайт и публикует результат в GitHub Pages.

## Работа с фотографиями

Для публикации используется отдельная оптимизированная копия фотографии. Оригиналы не изменяются.

```bash
python3 scripts/prepare_photos.py <source> <destination>
```

Стандарт по умолчанию: длинная сторона не более 1600 px, JPEG quality 84, исправление ориентации, удаление EXIF/GPS, сортировка по EXIF `DateTimeOriginal` при наличии даты и защита от случайной перезаписи опубликованных файлов.

## Локальный запуск

```bash
git clone https://github.com/dmitrylife/tarpen.github.io.git
cd tarpen.github.io
bundle install
bundle exec jekyll serve
```

Проверка production-сборки:

```bash
bundle exec jekyll build
```

## Публикация изменений

Основная ветка — `main`. После push в `main` GitHub Actions автоматически собирает и публикует сайт.

```bash
git pull origin main
# изменить кейсы, материалы или код
git add .
git commit -m "Describe change"
git push origin main
```

## Руководство

Подробный порядок добавления и сопровождения кейсов, фотографий, документов, обращений и ответов описан в **[MANUAL.md](MANUAL.md)**.

README описывает концепцию и архитектуру проекта; `MANUAL.md` служит рабочей инструкцией.

## Принципы публикации

- факты отделяются от предположений и оценок;
- состояние определяется наблюдаемым состоянием объекта, а не самим фактом переписки;
- документы и ответы сохраняются как часть проверяемой хронологии;
- причинно-следственная связь или исполнитель не устанавливаются без подтверждения;
- публикационные фотографии очищаются от лишних метаданных;
- структура данных сохраняется пригодной для автоматической обработки и расширения архива;
- проект сохраняет независимый и неполитизированный характер.
